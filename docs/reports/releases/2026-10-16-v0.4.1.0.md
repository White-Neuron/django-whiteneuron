# Release Notes: v0.4.1.0

**Date**: 2026-10-16  
**Type**: Feature release (no migrations, no breaking changes)  
**Scope**: Admin "About" page: application and base versions, release dates, runtime summary

---

## Summary

v0.4.1.0 adds an **About** page to the admin. Staff can see which version of the application and
of django-whiteneuron is running and when each was released, without asking a developer or reading
deployment logs. Superusers also get a short runtime summary for support. The page shows only what
these readers need. It never shows host or infrastructure details that would help an attacker
fingerprint the server.

---

## Added

### About page
- URL `/admin/about/` (name `admin:about`), sidebar **System → About** (Vietnamese: *Hệ thống →
  Thông tin ứng dụng*). Every active staff user can open it; other users are sent to the login
  page.

| Card | Who sees it | Content |
|---|---|---|
| Application version / Base version | all staff | the two versions with their release dates |
| Application | all staff | `NAME`, `VERSION`, `RELEASE_DATE`, `BUILD_ID` (12 characters), rows from `APP_INFO_CALLBACK` |
| Base platform | all staff | `django-whiteneuron`, its version and release date, changelog link |
| Runtime | superusers | Python, Django and Unfold versions, database engine, debug mode, time zone, server time, process start, uptime |

- Dates are formatted in the active language ("Oct. 15, 2026" / "Ngày 15 tháng 10 năm 2026"), and
  so is the uptime ("2 days, 3 hours" / "2 ngày, 3 giờ"). Django's own `timesince` has no
  Vietnamese translation, so the package formats the uptime itself.
- The process start time is read from the OS through `psutil` (already a dependency since 0.4.0.0).
  If `/proc` is restricted, the row is left out and the page still renders.
- Light, dark and every daisyUI theme are supported, and on phones the cards stack in one column.

### Settings

| Setting | Environment variable | Default | Notes |
|---|---|---|---|
| `VERSION` | `VERSION` | `"0.3.2"` | existing setting, also used by announcements |
| `RELEASE_DATE` | `RELEASE_DATE` | `None` | ISO date (`2026-10-15`); other text is shown as is |
| `BUILD_ID` | `BUILD_ID`, falls back to `GIT_COMMIT` | `None` | cut to 12 characters |
| `APP_INFO_CALLBACK` | (none, settings only) | `None` | `"path.to.func"`, `func(request) -> [(label, value), ...]` |

```python
# settings.py
APP_INFO_CALLBACK = "myproject.utils.app_info_rows"

# myproject/utils.py
def app_info_rows(request):
    return [("Tenant", "acme"), ("Region", "ap-southeast-1")]
```

The callback rows are shown to **every staff user**. Do not return secrets, URLs that contain
credentials, or internal addresses. If the callback raises, the error is logged as a warning from
`whiteneuron.base.app_info` and its rows are skipped.

### Package version
`whiteneuron.__version__` and `whiteneuron.__release_date__` are now defined. A test checks that they
match `pyproject.toml` and the `CHANGELOG.md` heading, so a release can no longer ship with a stale
version on the About page.

## Security

The page was reviewed for information disclosure. These are **never** shown, to any user:

- host name, OS and kernel version, CPU architecture
- IP addresses, file system paths, the Python executable
- database server version, connection settings, the cache backend
- the full dependency list with versions (useful for CVE lookup)

Debug mode and the runtime card are visible to superusers only. The view goes through
`admin_site.admin_view` (staff-only, `never_cache`). All values are auto-escaped, including rows from
`APP_INFO_CALLBACK`. Tests check that staff can't see the runtime card and that the runtime card
contains no host name, kernel version or secret-looking values.

## Tests
New `whiteneuron/base/tests_about.py` (9 tests):
- anonymous and non-staff users are redirected
- staff see both versions and the formatted release date, but not the runtime card or debug mode
- superusers get the runtime card, with no host name or kernel version in it
- the build id is cut to 12 characters, and a numeric `BUILD_ID` works
- a failing `APP_INFO_CALLBACK` and empty `VERSION` / `RELEASE_DATE` don't break the page
- callback rows are added to the Application card
- `__version__` / `__release_date__` match `pyproject.toml` and `CHANGELOG.md`
- the uptime is formatted in English and Vietnamese

## Compatibility / Upgrade

```bash
pip install -U django-whiteneuron==0.4.1.0
python manage.py collectstatic
```

- No migrations. All new settings are optional.
- If the project defines its own `UNFOLD["SIDEBAR"]["navigation"]`, add the link itself:
  `{"title": _("About"), "icon": "info", "link": reverse_lazy("admin:about")}`.
- If the project overrides `BaseAdminSite.get_urls`, keep calling `super().get_urls()` so the
  `about/` URL stays registered.
- To fill the page in deployments, set `VERSION`, `RELEASE_DATE` and `BUILD_ID` (or `GIT_COMMIT`)
  in the environment, for example from the CI pipeline.
- Translators: new msgids `About`, `Application version`, `Base version`, `Base platform`, `Build`,
  `Changelog`, `Debug mode`, `Package`, `Process started`, `Release date`, `Runtime`, `Server time`,
  `Time zone`, `Version`, `Visible to superusers only`, `On`, and the plurals `%(count)d day`,
  `%(count)d hour`, `%(count)d minute`.
- Docker base images `django-whiteneuron-{alpine,debian}:v0.4.1.0` are published by the release
  workflow; WN-Sense can set `BASE=v0.4.1.0`.

### Rollback
Revert to v0.4.0.2. There are no schema changes, and the new settings are ignored by older versions.
