# Release Notes: v0.4.0.0

**Date**: 2026-10-13  
**Type**: Feature release (minor bump: behavior changes, new app, new dependency)  
**Scope**: Admin theming, server monitoring, django-unfold 0.109, security hardening, performance

---

## Summary

v0.4.0.0 adds a daisyUI multi-theme admin (35 themes that also re-color Unfold) and a new
`whiteneuron.monitoring` app with a Grafana-style server dashboard. It upgrades django-unfold
from 0.99.1 to 0.109.0, closes a set of security issues found in a full review (stored XSS,
a GET that could delete rows through `?display_fields=`, an unauthenticated notification
WebSocket, spoofable client IPs, unscoped exports), and removes most per-request database work
from the activity logging, notifications and dashboard. Three migrations are included (indexes
and the monitoring table).

---

## Changes

### Added

- **Admin themes** — `scripts/gen-themes.mjs` compiles every daisyUI theme into
  `base/css/styles.css` and maps it onto Unfold's primary/base/font palettes. Picker in the user
  menu (**Themes**), persisted per browser, no flash on load. `WN_ADMIN_THEMES` limits the list (`[]` hides the
  picker).
- **`whiteneuron.monitoring`** — dashboard at *System → Server monitoring*:
  - Overview stats with sparklines and thresholds (uptime, CPU, memory, disk, load, throughput,
    5xx error rate, p95 latency).
  - System panels: gauges, per-core heatmap, CPU, load, memory, disk I/O, network, disk space.
  - Application panels from the existing request logs: requests/min by outcome, p50/p95/p99,
    status-code breakdown, Apdex, slowest endpoints (ids grouped as `:id`).
  - Process & dependencies: DB / cache round-trip, app RSS and threads.
  - Time ranges 5m–7d, auto-refresh, host selector, shared crosshair, shareable URLs,
    theme-aware, mobile layout.
  - Collection: `manage.py monitoring_collector` (or `--once`), Celery task
    `whiteneuron.monitoring.tasks.collect_metrics`; retention via `WN_MONITORING`.
- **Unfold 0.109 features** — avatar badge with today's unread notifications, sidebar
  sub-navigation (Celery "Schedules"), `SITE_VERSION`, dashboard card icon/description,
  theme-aware chart colors.
- **`base.queue.enqueue`** — email, export and GPT translation run on Celery when
  `WN_ASYNC_TASKS=True`, inline otherwise; a broker error after commit falls back to inline.

### Security

- Escaped all values in notification titles/bodies, notification admin and user grid headers;
  legacy stored notification HTML is sanitized (allowlist).
- `?display_fields=` accepts only known columns (Django called any other name on every row).
- The column picker ("display_fields" / "All") only offers fields shown on the change form
  (`fields` / `fieldsets` / `exclude` respected), never `password`; projects can hide more with
  `ModelAdmin.field_selection_exclude`.
- Notification WebSocket: staff only, per-user groups, `AllowedHostsOriginValidator`.
- Uploaded HTML preview served with `Content-Security-Policy: sandbox allow-scripts allow-popups`.
- Exports contain only the selected/visible rows and are private to the requester.
- Client IP read from the right of `X-Forwarded-For` (`TRUSTED_PROXY_COUNT`,
  `IGNORE_X_FORWARDED_FOR`); `ip:port` hops parsed in place.
- Guest auto-login validates `?next`; feedback "resolve" is POST-only; feedback targets must exist
  and be viewable; notification detail/redirect scoped to the owner.
- New-user signal no longer overwrites passwords set by `create_user()`; generated passwords use
  `secrets`, are masked in stored `Mail` rows and are never sent to the task broker; unverified SMTP connection removed.
- File integrity checks always hash the stored bytes (no cache that a same-size rewrite or a cache
  outage could fool).

### Performance

- Activity logging: cached VisitProfile id + throttled `last_seen` → 1 INSERT per request.
- Notifications: one `bulk_create` and one broadcast after commit per event.
- Indexes on activity timestamps, `VisitProfile.last_seen`, notification lookups.
- Dashboard KPIs/chart in 4 aggregate queries with a 60s cache; dates fixed to half-open ranges.
- Atomic rate-limit counters; UA patterns compiled once per worker; group lookups memoized per
  request; `list_select_related` on activity/blacklist/file/notification lists; notification list
  resolves linked objects per page; no session write on every page.
- Thumbnails/previews generated at upload (real JPEG, EXIF-aware); 14KB logo / 5KB favicon
  instead of a 187KB image; CSS spinner instead of a 29KB GIF.

### Fixed

- Grid view / page size / row buttons were stored on the shared ModelAdmin instance.
- `readonly_fields` declared as a list grew on every request.
- `App.__str__` returned a lazy proxy (crash on create); "Export selected" raised `TypeError`.
- Duplicate action copies M2M values and reports the real count.
- Chart.js could not parse oklch theme colors (converted to rgba); notification WebSocket could
  open parallel reconnect loops; the monitoring collector stopped when the cache was down;
  missing thumbnails were never regenerated.
- Sidebar logo/title missing on the monitoring dashboard and admin index; flash messages shown
  twice on the admin index.
- Changelist toolbar (filter button, grid toggle, page size) hidden for admins without
  `search_fields`; "Next" enabled on the last page; Previous/Next stuck disabled when Django
  ignores `?all` (more rows than `list_max_show_all`).
- Monitoring dashboard colors unreadable under several themes (white on white in luxury, invisible
  accents in black/business/cupcake); its controls are now daisyUI components.
- Markdown previews were unstyled: the classes `md2html_tailwind4` emits were never compiled (the
  Tailwind `@source` used an unsupported `python3.*` directory glob).
- Closed announcement dialog made every admin page scroll sideways on phones.
- `_(f"…")` messages that could never be translated; Vietnamese catalog updated (all strings
  translated).

## Compatibility Notes

- **Breaking / behavior changes**
  - `SECRET_KEY` is required when `DEBUG=False` (build commands such as `collectstatic`,
    `compilemessages`, `check` are exempt).
  - `WN_ASYNC_TASKS` is opt-in; enable it only with a running Celery worker.
  - Client IP auto mode now trusts the right-most public `X-Forwarded-For` hop. Behind proxies
    set `TRUSTED_PROXY_COUNT`; if the app is reachable directly set
    `IGNORE_X_FORWARDED_FOR=True`.
  - `UpdateCacheMiddleware`/`FetchFromCacheMiddleware` only with `USE_CACHE_MIDDLEWARE=True`.
  - New notifications store plain-text titles and JSON `changed_data` (old rows still render).
  - Removed `EXTENSIONS.modeltranslation` and `compressed_fields` (no longer read by Unfold);
    `hide_title` → `show_title`.
  - `ModelAdmin.request` remains available but is request-scoped (contextvar), not shared.
  - In the default light/dark modes daisyUI components (`ui-*`) take their base and primary colors
    from `UNFOLD["COLORS"]` instead of daisyUI's stock palette.
  - The *Server monitoring* sidebar link requires `monitoring.view_metricsample` (was
    superuser only).
  - Projects overriding `unfold/helpers/navigation_user.html` should compare with Unfold 0.109.
- **Schema changes**: `base.0028_perf_indexes`, `notification.0013_perf_indexes` (indexes only),
  `monitoring.0001_initial` (new table).
- **New dependency**: `psutil>=7.0.0`; `django-unfold>=0.109.0,<0.111` (capped: the package overrides
  Unfold templates, so each Unfold release is re-tested before the cap is raised).
- **Python**: >=3.13 (unchanged) — **Django**: >=6.0.8,<7.0.0 (unchanged).

## Upgrade Guidance

```bash
pip install --upgrade django-whiteneuron
```

1. Add `"whiteneuron.monitoring"` to `INSTALLED_APPS` and a sidebar link if you build your own
   `UNFOLD["SIDEBAR"]` (see README → *Server monitoring dashboard*).
2. `python manage.py migrate`
3. `python manage.py compilemessages` (or ship the bundled `.mo`).
4. Set `SECRET_KEY`, `TRUSTED_PROXY_COUNT` / `IGNORE_X_FORWARDED_FOR`, and `WN_ASYNC_TASKS=True`
   only if a Celery worker runs.
5. Run `python manage.py monitoring_collector` on each host (systemd service) or schedule the
   Celery task.

## Rollback

```bash
python manage.py migrate monitoring zero
python manage.py migrate notification 0012
python manage.py migrate base 0027
pip install django-whiteneuron==0.3.8.0
```

The base/notification migrations only add indexes; rolling back loses no data (monitoring samples
are dropped with their table).
